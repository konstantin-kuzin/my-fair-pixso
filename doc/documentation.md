# Принцип работы расширения «My Fair Pixso»

Документ описывает, из каких частей состоит расширение и как оно взаимодействует с сайтом Pixso. Расширение не является официальной частью Pixso: оно подключается к странице как сторонний скрипт и автоматизирует действия, которые пользователь мог бы выполнить вручную через меню.

## Архитектура в терминах Chrome

Расширение построено на **Manifest V3** и состоит из нескольких изолированных контекстов:

| Компонент | Где выполняется | Роль |
|-----------|-----------------|------|
| **Service worker** (`background.js`) | Фоновый процесс браузера | Таймеры автоэкспорта, переименование загрузок `.pix`, реакция на изменения настроек в `chrome.storage` |
| **Content script** (`content-script.js`) | Изолированный мир (isolated world) на вкладке `pixso.net` (в т.ч. во **всех фреймах** — см. `all_frames` в `manifest.json`) | Доступ к DOM, скрытие строк плагинов, кнопка в тулбаре, сценарий экспорта, доработки модалки публикации библиотеки, инжект вкладки `DOC` |
| **Скрипт экспорта** (`export.js`) | Контекст страницы (main world), подключается как `web_accessible_resource` | Клики и наведения там, где изолированный content script ограничен; обход **shadow DOM**; клики по чекбоксам публикации в main world |
| **Всплывающее окно** (`options.html` + `options.js`) | Маленькое окно по клику на иконку расширения | Чтение и запись настроек в `chrome.storage.local` |

Связь между частями: **`chrome.storage.local`** — общее хранилище настроек; **`chrome.runtime.sendMessage` / `onMessage`** — фон запрашивает у активной вкладки Pixso выполнить экспорт; **`postMessage`** — content script общается со страничным `export.js` для действий в main world (в т.ч. клики по чекбоксам в панели публикации). Сообщения помечаются `source: 'pixso-tuner'`; в мосте проверяется **`origin`** страницы, без требования `event.source === window` (иначе сообщения из isolated content script не доходили бы до обработчика в странице).

## Скрытие строк «Enterprise plugins»

В списке пользовательских плагинов Pixso отображаются закреплённые служебные пункты (классы вида `plugin-dropdown-li-0-user` … `plugin-dropdown-li-7-user`). Скрипт находит контейнер `.user-plugins-wrap` и удаляет из него элементы `.plugin-item`, попадающие под эти классы.

Поведение включается флагом **`trimPluginsListEnabled`** (по умолчанию включено). При изменении настройки content script перечитывает флаги и при необходимости снова обходит DOM. Наблюдатель **`MutationObserver`** отслеживает перерисовку меню и повторяет очистку.

## Кнопка сохранения в `.pix` на панели

В область верхней панели (слот `.top-menu--center--tools`) вставляется собственная кнопка с иконкой «сохранить». По нажатию запускается **`runExportPixFlow()`** — попытка программно воспроизвести цепочку: открыть меню файла при необходимости, открыть каскад **Export**, довести до видимости пункт **Pixso Design File (.pix)** и кликнуть его.

Реализация опирается на:

- селекторы вида `[command="export_pix"]` и `[command="export_file_menu"]`;
- симуляцию событий указателя/мыши (часть интерфейса на Vue ожидает полную цепочку событий);
- **`export.js`** — дублирование кликов и hover в контексте страницы, в том числе внутри теневых корней.

Флаг **`exportPixButtonEnabled`** отключает кнопку и удаляет её из DOM, если пользователь выключил опцию в настройках.

## Вкладка `DOC` в правой панели

Расширение добавляет дополнительную вкладку **DOC** в правый сайдбар Pixso (рядом с нативными вкладками). При активации вкладки:

- создаётся отдельная панель (`data-pixso-tuner="doc-panel"`) рядом с нативным скроллером панели;
- в панель подгружается HTML-шаблон из `doc-tab.html`;
- загружается JSON со ссылками (`links.json`) через `chrome.runtime.getURL(...)`;
- список сортируется по алфавиту (`localeCompare` для `ru/en`) и рендерится как кликабельный список.

Если в настройках отключена опция `docPanelEnabled`, content script удаляет инжектированную вкладку `DOC` и соответствующую панель из DOM.

### Как изменить содержимое панели `DOC`

Базовый контент панели хранится в двух файлах расширения:

- `links.json` — данные списка ссылок;
- `doc-tab.html` — статическая обвязка панели (заголовок, описание, контейнер под список).

Чтобы изменить набор ссылок, нужно править `links.json`. Формат файла — массив объектов вида:

```json
[
  { "name": "Button", "url": "https://pixso.net/app/design/..." },
  { "name": "Input text", "url": "https://pixso.net/app/design/..." }
]
```

Правила для элементов:

- `name` обязателен и должен быть непустой строкой;
- `url` обязателен и должен быть непустой строкой;
- элементы с пустыми или некорректными полями игнорируются при загрузке;
- порядок в `links.json` не является окончательным: перед рендером список всё равно сортируется по `name` через `localeCompare` для `ru/en`.

Практически это значит:

- чтобы **добавить** страницу, вставьте новый объект `{ "name": "...", "url": "..." }`;
- чтобы **изменить** подпись или адрес, отредактируйте существующие поля `name` / `url`;
- чтобы **удалить** ссылку, удалите объект из массива;
- если нужен визуальный псевдораздел, его можно сделать обычным элементом списка с названием вроде `- Foundation` или `—— Colors` — он тоже будет отсортирован вместе с остальными.

Если нужно изменить не только список ссылок, но и текст вокруг него, правьте `doc-tab.html`. В шаблоне должен остаться контейнер с атрибутом `data-pixso-tuner="doc-list-host"`, иначе `content-script.js` не сможет вставить туда список.

После изменения `links.json` или `doc-tab.html` нужно:

1. Открыть `chrome://extensions`.
2. Нажать обновление у расширения **My Fair Pixso**.
3. Перезагрузить вкладку Pixso, чтобы content script заново подхватил ресурсы.

## Модалка публикации библиотеки: порядок списка 

В модалке **Publish library** список компонентов в Pixso **виртуализирован**: в DOM одновременно находится только «окно» строк, позиции задаются через `style.top` / `transform`. Часть разметки живёт в **open shadow DOM**. Перестановка узлов `.item` внутри контейнера `.wrapper` вручную **ломает** прокрутку и высоту списка, поэтому расширение **не** пытается сортировать нативный список перестановкой DOM.

Вместо этого реализованы три слоя поведения.

### 1. Компактный вид и стабильность нативного списка

- Удаляются блоки превью (`.publish--detail--li-image-box` и варианты классов), добавляются стили компактной строки и сетки — чтобы нативный список оставался читаемым без оверлея.
- После мутаций и при остановке прокрутки выполняются отложенные проходы (`MutationObserver` на `.wrapper`, слушатели `scroll` / `scrollend`), во время активного скролла тяжёлые проходы не запускаются — чтобы не вызывать мигание у виртуального списка.

### 2. Сканирование и алфавитная сортировка «как в справочнике»

По кнопке вверху контейнера `.library-publish-container` скрипт пошагово прокручивает блок со списком от начала до конца и на каждом шаге собирает снимок видимых элементов `.item`:

- заголовки секций распознаются по разметке (группы в духе **Changes**, **Unchanged**, **Hide** — с нормализацией русских/английских подписей);
- строки компонентов извлекаются по имени, чекбоксу и статусу; учитывается вертикальное смещение строки (`top` / `translateY`), чтобы при отсутствии заголовка в кадре строка относилась к **последней** видимой выше секции;
- внутри каждой группы имена сортируются **по алфавиту** (`localeCompare` с числовым режимом);
- дубликаты по паре «группа + имя» сливаются.

Результат не подменяет порядок узлов Vue, а передаётся в отдельный UI.

### 3. Оверлей со списком и связь с настоящими чекбоксами

Строится панель **поверх** области списка (inline внутри scroll модалки или запасной fixed-блок). Исходный `.wrapper` при активном режиме визуально скрывается классом `pixso-tuner-publish-sorted-active`; кнопка **«Исходный вид»** снимает оверлей.

Чекбоксы в оверлее синхронизируются с реальными чекбоксами модалки: по имени и подсказке позиции ищется соответствующая строка; при необходимости список **прокручивается** к нужной позиции. Клик по «настоящему» чекбоксу выполняется через мост **`export.js`** (`click-publish-checkbox`): в isolated world у части узлов клик не засчитывается (в т.ч. нулевой размер инпута, узлы в shadow), поэтому в main world диспатчатся события указателя/мыши и при необходимости вызывается `click()` на input.

- Для секции **Changes** в заголовке оверлея показывается счётчик вида `selected/total`; если выбрана только часть строк, групповой чекбокс переводится в состояние **`indeterminate`**.
- В режиме **Pumped-up view** добавляется поле поиска. Поиск фильтрует строки оверлея по подстроке в имени компонента, при этом заголовки секций **Changes / Unchanged / Hide** остаются видимыми всегда.

При закрытии модалки оверлей и кнопка сканирования снимаются.

## Автосохранение по расписанию

В **`background.js`** создаётся периодический **`chrome.alarms`** с именем `pixso-tuner-auto-export`. Интервал в минутах задаётся в настройках (от 1 до 120). При срабатывании аларма service worker:

1. Находит **активную вкладку** текущего окна.
2. Проверяет, что URL — домен `pixso.net`.
3. Отправляет в content script сообщение **`pixso-tuner-auto-export-pix`**.

Content script при получении сообщения вызывает тот же **`runExportPixFlow()`**, что и при ручном нажатии на кнопку. Важно: экспорт привязан к **активной** вкладке с открытым Pixso; если в фокусе другая вкладка, автоэкспорт для фоновой вкладки не выполняется.

При изменении настроек автоэкспорта таймер пересоздаётся (`syncAutosaveAlarm`).

## Шаблон имени загружаемого файла

При включённой опции **`renamePixDownloads`** service worker подписан на **`chrome.downloads.onDeterminingFilename`**. Для загрузок, похожих на экспорт Pixso (файл `.pix`, реферер или URL с `pixso.net`, либо `blob:`), подставляется имя по шаблону:

- `{{date}}` — метка даты и времени;
- `{{title}}` — основа имени из исходного файла (очищенная от недопустимых символов);
- `{{raw}}` — исходное имя файла.

Кэш настроек переименования обновляется при старте и при любых изменениях `chrome.storage.local`, потому что обработчик `onDeterminingFilename` должен синхронно вызвать **`suggest()`** один раз на загрузку.

## Настройки (popup) и флаги

В `options.html` / `options.js` сохраняются флаги в `chrome.storage.local`, которые влияют на поведение content script и service worker:

- `trimPluginsListEnabled` — скрытие закреплённых пунктов `Enterprise plugins`;
- `exportPixButtonEnabled` — показ/скрытие кнопки сохранения `.pix`;
- `docPanelEnabled` — показ/скрытие вкладки `DOC`;
- `renamePixDownloads` и `pixDownloadFilenameTemplate` — переименование скачиваемых `.pix`;
- `autosaveFolderEnabled` и `autosaveFolder` — подпапка в `Downloads`;
- `autosaveIntervalMinutes` — интервал автоэкспорта.

## Ограничения и устойчивость

- Интерфейс Pixso может меняться: селекторы и классы в теории могут перестать совпадать; тогда потребуется обновление расширения.
- Автоэкспорт и кнопка не обходят права доступа в файле Pixso — они лишь автоматизируют UI.
- Полный список компонентов для сортировки доступен только после **сканирования с прокруткой**; без API Pixso расширение не получает весь каталог иначе, чем обходя видимые фрагменты виртуального списка.
- Содержимое вкладки `DOC` зависит от статического `links.json` в расширении; если список страниц изменился в Pixso, JSON нужно актуализировать вручную.
- Расширение запрашивает доступ только к **`https://pixso.net/*`** и **`https://*.pixso.net/*`**.

## Краткая схема потока данных

```
popup / options.js
       │ chrome.storage.local.set(...)
       ▼
background.js ◄──── storage.onChanged ────► content-script.js
       │ alarms                                        │ MutationObserver
       │ sendMessage (auto-export)                     │ DOM + export-bridge (postMessage)
       ▼                                               ▼
активная вкладка Pixso ─────────────────────► меню Export → загрузка .pix
       │                                                    │
       │                                                    ├── модалка Publish: скан + оверлей, клики чекбоксов через export.js
       │                                                    └── вкладка DOC: html-шаблон + links.json → сортированный список ссылок
       │
       └── onDeterminingFilename (переименование .pix при скачивании)
```
